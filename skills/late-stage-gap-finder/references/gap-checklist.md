# Pre-signature gap checklist

Run every applicable line. A line that does not apply is marked N/A in the working notes, not skipped silently, so the user can see coverage.

## Contents
- Order form
- Main agreement
- DPA and security exhibit
- SLA
- SOW
- Cross-document numeric checks
- Signature mechanics

## Order form

- [ ] Legal entity names match the main agreement exactly, including suffixes
- [ ] Quantity, unit, and unit price stated, and they multiply to the total
- [ ] Billing frequency and first invoice date
- [ ] Payment terms stated, and they match the MSA
- [ ] Start date and end date, not just a term length
- [ ] Currency
- [ ] PO number field, if the buyer requires a PO
- [ ] What happens on overage
- [ ] Which entity's terms govern, referenced by name and date
- [ ] Any special terms that override the MSA, marked as overriding

## Main agreement

- [ ] Liability cap present, with a stated amount or formula
- [ ] Carve-outs from the cap enumerated
- [ ] Consequential damages waiver, and whether it is mutual
- [ ] IP indemnity present and scoped
- [ ] Confidentiality obligations, with a term
- [ ] Term, renewal mechanics, and notice period to cancel
- [ ] Termination for cause, with a cure period
- [ ] Termination for convenience, present or deliberately absent
- [ ] Effect of termination: data return, deletion, final invoicing
- [ ] Survival clause covering confidentiality, liability, payment
- [ ] Governing law and venue
- [ ] Notice provisions with a method and an address
- [ ] Assignment, including change of control
- [ ] Insurance requirements, and whether current coverage meets them
- [ ] Publicity and logo rights
- [ ] Every defined term used is actually defined
- [ ] Every exhibit referenced actually exists and is attached

## DPA and security exhibit

- [ ] DPA present where personal data is processed
- [ ] Roles stated correctly: controller, processor, sub-processor
- [ ] Subprocessor list attached or referenced, and current
- [ ] Notice mechanism for new subprocessors
- [ ] International transfer mechanism where relevant, such as SCCs
- [ ] Breach notification window, and whether the company can meet it
- [ ] Deletion and return timelines, and whether the system can meet them
- [ ] Audit rights, and what the company committed to
- [ ] Security controls listed, each one currently true today
- [ ] Data residency commitments the architecture can actually deliver
- [ ] AI and model-data handling addressed where the product uses model providers

## SLA

- [ ] Uptime target, with the measurement window defined
- [ ] What counts as downtime, and what is excluded
- [ ] Maintenance windows carved out
- [ ] Service credits, with an amount and a claim process
- [ ] Credit cap
- [ ] Whether repeated misses create a termination right
- [ ] Support response times by severity, with severity defined
- [ ] Support hours and time zone

## SOW

- [ ] Deliverables, listed and dated
- [ ] Acceptance criteria, and what happens on non-acceptance
- [ ] Buyer dependencies stated, since delays caused by the buyer are the common dispute
- [ ] Change request process
- [ ] Fees: fixed, time and materials, or milestone
- [ ] Whether payment is contingent on acceptance
- [ ] Who owns work product

## Cross-document numeric checks

Compare across every supplied document and list any disagreement:

- Price and total contract value
- Quantity and seat or unit counts
- Start and end dates
- Term length
- Notice periods
- Payment terms
- Retention and deletion periods
- Uptime targets
- Support response times
- Liability cap, where it appears in more than one place

## Signature mechanics

- [ ] Signature blocks for both parties, with title lines
- [ ] The signer on each side has authority
- [ ] Effective date defined, and consistent with the start date
- [ ] All exhibits initialled or referenced as required
- [ ] Counterparts and electronic signature clause present
- [ ] The version being signed is the version that was last negotiated
